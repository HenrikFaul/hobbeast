## Rollback strategy

- **Code changes in this pass** (typecheck script, CI wiring, `client.ts` log fix): revert the
  individual commit; no DB migration involved.
- **Docs added** (`PRODUCTION_READINESS_BASELINE.md`, `PRODUCTION_RISK_REGISTER.md`,
  `HISTORICAL_SECRET_EXPOSURE.md`): additive; no rollback needed.
- **Future DB migrations** (SECURITY DEFINER Round B): each ships as its own timestamped,
  append-only migration with an explicit rollback SQL or strategy, per the repo migration rule.

## Review cadence

Re-evaluate this register at every release gate and after any operator action (rotation,
migration approval, dep bump). Update statuses in place; never delete historical rows.
