# AI/Dev Prompt — v1.8.2 (Profile privacy contract foundation)

- **Date:** 2026-08-21
- **Version:** 1.8.2
- **Scope:** Prompt 03 — identity, onboarding, profile and privacy.
- **Status:** PARTIAL / PRIVACY HOLD; local repository candidate only.

## Objective

Define an explicit public-profile DTO whitelist that cannot pass email, phone, address,
precise coordinates, birth data, or unknown fields to public consumers.

## Delivered

1. Added `buildPublicProfileDto` and a forbidden-key contract.
2. Added six tests for whitelisting, forbidden fields, sparse input, normalization, and
   input immutability.
3. Corrected unit-test evidence: 55 to 61 tests.

## Not delivered

- Replacement of the runtime `Profile` `select('*')` call site.
- A column-safe public view/RPC, RLS persona tests, onboarding completion, deletion,
  and block/report privacy boundaries.
- Production deployment or publication.

## Continuation instruction

Treat the client DTO as defense in depth only. Do not mark profile privacy `PASS` until
the server-side data projection and RLS/persona behavior are proven.

## Release decision

`HOLD`: the pure contract is useful, but it is not a database security boundary.
