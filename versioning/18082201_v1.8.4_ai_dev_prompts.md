# AI/Dev Prompt — v1.8.4 (Virtual Hubs 2.0 guarded foundation)

- **Date:** 2026-08-22
- **Version:** 1.8.4
- **Scope:** Prompt 05 — Virtual Hubs 2.0 and latent community engine.
- **Status:** PARTIAL / RELEASE HOLD; local repository candidate only.

## Objective

Harden the legacy hub path with the smallest regression-risk increment: enforce an admin
boundary, separate real demand from generated/unknown profiles, define deterministic hub
identity, and define a scoped membership plan without applying an unsafe partial snapshot.

## Delivered

1. `virtual-hubs-admin` requires an authenticated admin for every action.
2. `generate-hub-events` no longer trusts a body-controlled `_cron` flag; AI qualification
   counts only explicit real users and fails closed when `user_origin` is unavailable.
3. Added deterministic identity, demand-count, match, and scoped membership-plan helpers
   plus 11 unit tests.
4. Admin UI consumes authenticated Edge contracts, exposes real/generated/unknown counts,
   and blocks destructive refresh and event writes while still allowing safe preview/config.
5. Added bounded Gemini timeout and response validation, a production target-ref assertion,
   a tracked-`.env` release gate, a requirement matrix, and rollback documentation.

## Not delivered

- No database migration, Edge deployment, secret rotation, or production publication.
- Nullable legacy uniqueness, the directly callable destructive refresh RPC, transaction/job
  lock, durable idempotency/audit, target schema, RLS, Deno, Playwright, and live cron proof remain open.
- Scheduler activation remains blocked pending a server-held signature, replay protection,
  and durable idempotency.

## Continuation instruction

Do not activate or deploy the hub automation. First obtain owner/security approval for
credential rotation and `.env` untracking, then implement one reviewed migration for
non-null hub identity, scoped reconciliation, job locking, and audit. Verify in local
Supabase with persona/RLS tests before any target-project deployment.

## Rollback

Revert the v1.8.4 source slice as one unit. No database rollback is required because this
round intentionally ships no migration or external mutation.

## Release decision

`HOLD`: source contracts improved, but production safety and runtime evidence are incomplete.
