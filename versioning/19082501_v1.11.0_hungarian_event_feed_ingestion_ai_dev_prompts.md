## Business request

Keep good Hungarian brand copy instead of silently overwriting it. Expand the limited current
event inventory with a daily-capable in-house catcher for RSS, Atom, ICS, Schema.org Event and
HTML-discovered feeds. Start from the supplied Hungarian source workbook, normalize usable
programs into Hobbeast's own event model, assign searchable categories, publish only sufficiently
complete and safe items, poll responsibly and preserve full monitoring/audit evidence.

## Source evidence and interpretation

The supplied `Magyar_Program_RSS_Master_Lista_V4.xlsx`, sheet `RSS Source Master List V4`, contains
185 unique source IDs and endpoints across 45 columns. It contains no duplicate ID/endpoint, but
all 185 rows lack current health/last-check proof; only 26 contain a non-empty legal-basis note.
Sixty-seven endpoint strings are strict credential-free HTTPS URLs and 118 require URL review.

Therefore the workbook is a discovery inventory, not a permission list and not a verified feed
catalog. The committed JSON snapshot preserves its non-empty cell values. The generated seed
creates all 185 rows as `pending_review`, `legal_review_status = pending`, `robots_allowed = NULL`
and `enabled = false`; no workbook phrase is upgraded into legal or robots approval.

## Architecture decision

1. Keep native Hobbeast events and the Eventbrite/Ticketmaster/SeatGeek adapters intact. Add
   `feed` as one more external source in the existing public projection and UI attribution.
2. Parse RSS 2.0, RSS 1.0/RDF, Atom, ICS, structured Schema.org Event JSON-LD and bounded HTML in
   a pure TypeScript core. Publication dates are metadata, never substitutes for explicit event
   start dates.
3. Normalize into the existing `external_events` model and the exact 17-category Hobbeast
   taxonomy. Quarantine missing dates, unsafe URLs, parser blockers and low-quality records.
4. Register every endpoint server-side. The client supplies only a source ID; it can never submit
   an arbitrary fetch URL.
5. Claim enabled sources through database leases. Store a SHA-256-addressed raw sample as
   service-only, 14-day evidence, then atomically deduplicate, quarantine/publish or cancel.
6. Keep scheduling dormant by default. HMAC secrets, hosted deployment and per-source approvals
   are explicit operator steps, not migration side effects.

## Implemented scope

### Source registry and deterministic seed

- `supabase/seeds/hungarian_event_feed_sources_v4.json` contains the 185-candidate snapshot.
- `scripts/generate-event-feed-seed.mjs` validates source IDs, publisher/country/control-character
  contracts, normalizes only strict HTTPS URLs and generates the data-only migration.
- `bun run event-feeds:validate` checks 185 total, 67 strict HTTPS, 118 held and byte-for-byte seed
  reproducibility. `ON CONFLICT DO NOTHING` protects a later reviewed row from seed overwrite.

### Parser and network boundary

- RSS 2.0, RSS 1.0/RDF and Atom with explicit event-date extraction and same-host discovery.
- ICS UID, recurrence identity, timezone, all-day and cancellation handling.
- Schema.org `Event`, subclasses and recognized `@graph`/collection extraction. Date-only values
  remain all-day values with no invented 01:00/02:00 clock time. A timezone-less date-time needs
  the audited timezone stored on its source or is quarantined. Hungarian candidates receive
  `Europe/Budapest` as parsing evidence while remaining pending and disabled.
- Complete-snapshot evidence is format-specific: RSS/Atom channels/feeds, complete ICS calendars
  and explicit Schema.org collections/graphs may age missing items. A standalone Event,
  generic/empty JSON, soft-error envelope, HTML discovery or parser-capped result never can.
- XML DTD/ENTITY rejection, 2 MiB body, 200 item and bounded-string limits.
- Credential-free HTTPS/443 only, exact registered FQDN, no IP literals, DNS A/AAAA global-address
  validation before every request with abortable resolver work, then a Deno-native direct
  connection to the validated address with an exact peer-IP check and TLS certificate/SNI
  verification against the original FQDN. Manual same-host redirects repeat the full boundary;
  headers and decoded bodies remain bounded. Chunked responses allow at most 4,096 chunks and
  256 KiB of framing overhead.
- ETag/Last-Modified conditional requests and 304 no-change completion are bound to the exact
  canonical structured endpoint. Redirected or HTML-discovered resources neither receive nor
  retain the canonical validators; a validator/resource mismatch fails closed.
- RFC 9309-oriented product-token/path matching, percent-encoding normalization, `/robots.txt`
  preflight before the initial endpoint, every redirect target and every HTML-discovered feed.
  Temporary robots failures and 429 fail closed.

### Database and publication safety

- Source, run, raw payload, normalized item and cron-dispatch ledgers with RLS/revoked client
  grants and service-only mutation RPCs.
- Probe runs are allowed only for an exact registered HTTPS host and always commit to quarantine.
- Normal publish requires approved review, approved legal status, robots evidence, enabled source,
  live robots allow, minimum quality and no parser blocker at both claim and commit boundaries.
- Feed identities are namespaced and idempotent. Raw bodies deduplicate by source/hash while an
  append-only observation row retains run-level evidence and renews the bounded 14-day TTL.
- A cancelled upstream occurrence deactivates its published row. Disappearance requires three
  successful parser-proven complete snapshots; HTML, capped parses and arbitrary JSON/error
  envelopes cannot age records out. A normal 304 narrowly revalidates still-published active
  items, while a probe 304 never extends visibility.
- Direct browser `SELECT` on `external_events` and all raw payload access are removed. The public
  RPC exposes only positive, active, fresh/aging supply.
- Historical service-role resolver exposure is revoked. Local-places and event-feed cron commands
  call secret-free runtime functions; credentials are never interpolated into `cron.job.command`.

### Edge and admin operations

- `event-feed-ingest` supports status, probe, manual sync, audited review and scheduled due-sync.
- Manual actions require a user JWT plus `providers.manage` before any service-role status or
  claim. Review uses the caller-scoped client so the SQL capability boundary cannot be bypassed.
- The Edge request stream is consumed once, capped at 16 KiB and decoded as fatal UTF-8 before
  auth/HMAC work, eliminating cloned/double-buffered bodies and rejecting undeclared overflow.
- Scheduled calls sign the exact raw body and timestamp, require a matching UUID nonce header,
  enforce five-minute skew and consume a one-time nonce/body digest before source claims.
- Admin **Feedek** exposes all 185 candidates through server-side search and pagination without
  presenting raw counters as proof of an active public source. Approval requires exact FQDN,
  legal evidence, robots evidence, poll interval, quality threshold, reason and audit/idempotency
  keys.
- Scheduled due-sync claims two sources per round and is bounded to 15 rounds / 30 claims,
  concurrency two and a 60-second budget. An abort signal cancels in-flight resolver/fetch work
  at the deadline; the database `pg_net` request uses a 90-second timeout. The default two-minute
  dispatcher can drain backlog across invocations while each source still obeys its reviewed
  polling interval; scheduling remains an explicit opt-in and no cron is installed by release.

## Non-regression contracts

- Preserve all routes, auth/role/RLS boundaries, native/external event flows, RSVP/waitlist,
  organizer/admin tools, trust/privacy controls, categories, filters and provider adapters.
- Do not publish from the workbook, a successful HTTP request, a parser score or an admin checkbox
  alone. Every independent gate must pass.
- Do not fetch caller-supplied URLs, wildcard hosts, cross-host redirects, private/reserved DNS
  answers, non-HTTPS resources or a path disallowed by live robots policy.
- Do not expose raw provider bodies, service-role values, cron HMAC secrets, error internals or
  unpublished/quarantined records to browser roles.
- Do not create a cron schedule or enable a source automatically during migration/deployment.
- Keep v1.10.0 media, motion/reduced-motion behavior, full hobby catalog and bundle budgets intact.
- An authenticated production fixture that is skipped remains `NOT_RUN`, never PASS.

   `bqdvqmpwccsxumzijspj`, `event-feed-ingest` is deployed `ACTIVE` version 1, and the explicit
   project-ref/post-deployment dry-run evidence is recorded above.

4. Run a non-publishing probe, inspect robots and quarantined normalization, then approve and
   optionally enable that single source.
5. Only then call `schedule_external_event_feed_daily(<cron>)` and observe one complete run.
6. Inspect hosted permissions/logs for the legacy resolver exposure and rotate the service-role
   credential if hosted evidence shows the old callable path was ever present or used.
